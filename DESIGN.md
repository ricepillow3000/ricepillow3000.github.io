# John Nguyen · Interactive Resume — Design Bible

> **This file is mandatory.** Every design session (new design, edit, "make it pop", polish, animation, sound, copy on screen, layout fix) starts by reading this whole file. Nothing gets designed until the checklist in section 0 is done. If a request conflicts with a rule here, say so and ask, unless the request explicitly overrides the rule. When a new rule is agreed, add it here in the same session.

Source of truth for tokens in code: `src/styles/tokens.css`. If a value changes there, update the frontmatter above too.

---

## 0. Before you design anything (checklist)

1. Read this file top to bottom, especially **2. Hard rules** and **13. Decision log** (so you don't bring back something John already rejected).
2. Name the screen(s) you will touch and re-read their section in **9. Components**.
3. Design inside the system: tokens, fonts, shapes, motion and sound rules below. Original work only, inspired by Persona 5, never a copy.
4. Keep it simple. Don't over-engineer, don't add libraries for what GSAP + CSS already do, don't bloat the page with text.
5. After the change, **prove it** (section 12): tests, click-everything, phone + desktop sweep, width scan, screenshots you actually look at, Lighthouse, Impeccable detector, Vercel guidelines pass.
6. Save (commit), publish the preview with **every** asset, verify the published copy.
7. Report back to John: do the work first, then a short summary a 6th grader can follow, plus one simple visual (table, before/after, or ASCII sketch).

## 1. Purpose, audience, voice

- **The problem:** plain white-and-black paper resumes are boring and "have no soul". John rejects that trend.
- **The solution:** his resume as a fun, intriguing, interactive game, built by **directing a crew of AI agents**. The site itself is the proof of the skill ("CASE 00 · THIS SITE").
- **Personal project.** Say so. Don't imply a client or employer.
- **Target:** AI Solutions Engineer internships and co-ops (tech/software tone: game first, professional underneath).
- **The #1 action:** connect on **LinkedIn**. PDF and email are the escape hatches.
- **Recruiter reality:** a 7 to 10 second skim. Proof numbers must be visible fast (727 of 728 checks, 199 of 201 errors, 5,022 → 710 false alarms, 2,000+ tests, 7,700+ lines).
- **Fast path always exists:** "Quick View (1-page resume)" on the title screen and a real PDF.
- **Voice:** confident, playful, never begging, never nerdy-dense. "Consider it stolen." energy, not "please hire me".

## 2. Hard rules (never break)

**Content and tone**
- No "HIRE ME", no begging. The only availability signal is the small line **"Status: open to opportunities"**.
- **Never show the phone number** anywhere: site, build, PDF, OG image. (The published PDF once leaked it; always scan the published PDF.)
- No codename **"PIRATE"** anywhere (John cringed). No pirate flavor in labels.
- **No emojis** in the site. Use drawn stars (`.ff-star`), SVG icons, or text.
- No game-console button symbols (no △ ○ ✕ □). Key hints use keyboard keys.
- Role wording: **"AI Solutions Engineer"** (calling card says "an AI solutions engineer"; elsewhere "AI Solutions Engineer in training").
- Fun facts, exact: "I play drums (200+ BPM on a good day).", **"I love Pierce The Veil."** (full band name, never "PTV"), "Genuinely scared of bees and wasps."
- **Colons and semicolons:** use ":" only to introduce a list or a label (e.g. "6 workflows: lint, security scan, 3 test suites", "Dean's List: Fall 2025, Spring 2026", "Status: open to opportunities"). Never ":" or ";" in casual sentences; use a comma.
- Skill levels are honest and on one scale: **LV out of 10** everywhere (Python is **LV 5**). No second "RK 90" style number that contradicts it.
- Side quests and every page stay **short**. Less wordy beats complete; details live in Quick View and the PDF.

**Originality**
- Inspired by Persona 5, **never a 1:1 copy**: no Atlus assets, screens, logos, fonts, music, text or character art. (Approved exceptions, John's calls, always in our own design: the motto TAKE YOUR TIME, the departure board's LET US START THE GAME, and the line map's station names YONGEN-JAYA, SHIBUYA, AOYAMA-ITCHOME, SHINJUKU, AKIHABARA, KICHIJOJI.) (Early asks for a "1:1 recreation of the P5 pause menu" were reshaped into an original system for this reason.)
- No AI-generated portrait of John (scrapped, see decision log). No fake "AI art designer" look.

**Visual no-gos (John removed these)**
- No oil/paint splatters, no white splatter lines, no squiggles, tally marks or X marks.
- No stray white lines or bands in the background (the cropped arrow on tall screens counted).
- No walking crowd or crosswalk on the title.
- Nothing that reads as wooden planks (menu background).
- No generic "Google Doc Arial" look for body text.
- No speedometer gauges (GPA is a clean comic card).
- No thick colored stripe down one side of a box (`border-left: 4px solid ...`), the classic AI-generated-UI tell. Use a hard offset shadow or a slab instead.
- No plain black boxes with text dumped inside (side quests).
- Nothing flat: cards need depth (layered sheets, hard shadows, pins, tape).
- Don't bloat or shove information at the visitor.

## 3. Design DNA: what makes it feel Persona-5-inspired

From John's research notes (kept verbatim in spirit):

1. **Thematic personality.** Rebellious, high-contrast red-and-black punk style with blocky typography. Pop art + street art + graffiti + high-contrast anime aesthetics.
2. **Snappy timing and overshoot.** Zero slow fades. Elements slam in within a few frames using steep ease-out, overshoot slightly and snap back ("paper cutouts slammed onto a table").
3. **Staggered orchestration.** Background, art and text enter 2 to 4 frames apart so the screen builds in rapid layers.
4. **Visual misdirection.** Fast lines, stars, slashes or ink pull the eye while the screen swaps underneath; the hard cut feels seamless.
5. **Layered depth.** Foreground, midground and background move at different speeds; static screens keep subtle idle motion so nothing feels frozen (but no endless marquees, see 7).
6. **Ransom-note typography.** Letters jitter, tilt and invert colors on hover.
7. **Frame-accurate sound.** Sharp, percussive foley (paper tears, crisp clicks, whips) on the exact frame an element lands.
8. **Hand-crafted uniqueness.** Every sub-page has its own visual system (Missions = wanted posters, Skills = party stat list, Stats = ID card, Side Quests = route map, Different = comic page, System = settings sheet). Don't recycle one template.
9. **Asymmetric, broken-glass frames.** Jagged, diagonal, skewed boxes; avoid parallel lines.
10. **Flat, hard-edged rendering.** Flat color blocks, hard value transitions, stark black ink. No soft gradients, blurs or soft drop shadows (the background's red vignette is the one soft exception).
11. **Halftone (Ben-Day dots) as accents only**, never behind body text.
12. **"No time pressure", but recruiter-friendly.** Bold and busy is allowed because the visitor explores at their own pace, yet every animation is skippable and the fast path is one click away.

## 4. Color

- Core triad: **red `#E5191C`, black `#0B0B0B`, white `#F5F5F0`**, plus **yellow `#FFE11A` for highlights only** (loot, key numbers, stars, focus, sticker pops).
- Skill level bars are **yellow** (red on the selected row; John, Nov 18: "make the skill bars yellow and red"). Teal survives only as small accents (the GPA flip sticker, the CLEARED glitch edge); pink is retired.
- Two cards side by side must not be "the same red twice": same family, different interior shapes, patterns or fonts (Meliona vs ARCAS).
- Contrast: body text ≥ 4.5:1. Numbers on stars: **black on yellow** (red stars with outlined white numbers failed contrast).
- **Yellow text on red fails** (3.6:1). Put yellow text on a black slab, or use white/black on red.
- Dimmed states (other skills while one is lit) stay readable: dim to about 60%, not 45%.
- `color-scheme: dark`; **theme-color black** (`#0B0B0B`, Nov 19: browsers and the Claude app tint their bars and frames with it, and red read as a thick red border round the station on a phone held sideways).

## 5. Typography

- **Big titles only** get ransom letters (cut-out boxes, mixed fonts, ±12° tilt, small hops, medium chaos, jitter on hover only).
- Everything readable uses **Barlow Semi Condensed** (body) and **Barlow Condensed bold italic** (labels). Simple, legible, on-theme.
- Section words and numbers: **Anton**, slanted; labels and buttons: **Bebas Neue**; typewriter lines: **Special Elite**; handwriting: **Permanent Marker** (calling card only).
- Dense text sits in a **slanted box with straight text** (box tilts, text stays level, ~70 characters max per line).
- `font-variant-numeric: tabular-nums` on all counters; `text-wrap: balance` on headings, `pretty` on paragraphs (no lonely last word).
- Screen readers get plain text for every cut-out title (`.sr-only` copy), and cut-out names carry `translate="no"`.

## 6. Shape and depth

- Jagged, layered shapes: 5 to 8 point `clip-path` polygons, stars and starbursts, torn paper. These are the brand; keep them even if a linter calls them "organic clip-paths".
- **Hard offset shadows** (no blur) in red, black, white or yellow; stacked paper sheets behind cards; red pins and translucent tape.
- No rounded corners except speech bubbles.
- Bullet lists never get cramped: use **tilted sticker strips** (one fact per strip, outlined star tab, alternating white/black, space between) or **slanted black number tags** (01, 02...) with hanging text.

## 7. Motion

- Engine: **GSAP** timelines + CSS. **Anime.js** is used for exactly one thing (slam-in on scroll), imported as two small pieces (`animejs/animation`, `animejs/utils`) and **lazy-loaded** so the first screen stays fast. Don't spread it further; GSAP stays the main engine.
- Enter: 0.2 to 0.4s, steep ease-out, overshoot and settle; stagger 2 to 4 frames.
- **Every big animation is skippable** with a click or Esc (`timeline.progress(1)`); Esc during a transition skips first.
- **Respect reduced motion** (OS setting and the SYSTEM toggle): swap motion for instant changes; stop idle loops.
- **Every chapter has ONE signature entrance, however you get there** (John, Nov 18: "every tab when switching has a different transition"; the guided ride used to play the same NEXT STOP train five times in a row). `CHAPTER_STYLE` in `src/main.js`: STATS = **THE DROP**, MISSIONS = **case file**, SKILLS = **NEXT STOP** (inside the train), SIDE QUESTS = **city billboard**, MY EDGE = **comic panels**, CONTACT = **calling card**, SETTINGS = **security monitor**, the secret page = **breaking glass**. Back to THE PLAN = THE RISE, Quick View = paper. THE PLAN, NEXT EPISODE, the stop dots, the menu and the number keys all play the destination's move, so the ride start to finish shows six different ones (a test rides it and checks). Subway doors and blinds were retired (a second train, and a generic wipe). Overlay class names must be unique (a wipe once used `.route`, which the Side Quests page also uses, and it broke).
- **Film cuts (the site should feel like a short anime movie).** Studied from Lusion's scroll story (lusion.co: a pinned scene split into weighted "shots", the frame flies at the camera, a scene the camera travels through, a title riding the motion, a hard cut; and "keep scrolling" to roll the next page). Each cut is ~1 to 1.4s, skippable, instant with reduced motion, and has ONE memorable beat:
  - **THE DROP** (board -> any page): the board rushes at you and splits on a jagged seam, you are on a rooftop over the night city, you drop past a skyscraper's windows (motion-blur smear grows with speed, speed lines), the chapter name rides the fall in cut-out letters, white star-flash landing.
  - **THE RISE** (back to the board): the page falls away below, you rocket up the tower and burst over the roof into a semi bird's-eye view of the city, "THE BOARD" sign, star-flash.
  - **NEXT STOP** (SKILLS' entrance): **from inside the train car** (Nano Banana interior `interior.webp`: ring hoops, plain light strip, bench; windows keyed see-through). Tunnel lights streak past, the car rocks, the station glides into the windows and stops; its sign (fitted inside one window pane, the camera aims at that pane on phones) reads the next chapter; ding-dong; star-flash.
  - **SIDE QUESTS = THE SQUARE** (Nov 20, John: "make it look like an actual billboard instead of a poster in front of a building... the middle of a Tokyo square, other mini advertisements, our star design, our philosophy, our name, filler billboards... the biggest in the middle is SIDE QUESTS... digital, attached to the building with the same textures"). An original night scramble-crossing square (Gemini, Nano Banana Pro, toon style; a fake vertical "word" on one building painted out), under a **red-and-black sky** (Nov 21, John: "make the sky more Persona 5 theme, red and black"): **a smooth fade, never bands** (Nov 21, John: "the black layering is very blocky and very noticeable, blend it in": the first pass used hard cel bands): black at the top melting through deep crimson to a bright red horizon along a slight slant, a touch of fine grain so the gradient never steps, a faint halftone texture in the red that fades in and out softly, and feathered dark rays from behind the big tower's crown that fade toward the horizon; the dark buildings stand out against it and the screens still lead. The sky was found by its smoothness and its own colour per row (ink lines and windows stop it), grown into the old grey glow round each rooftop lamp and down through the horizon haze; each lamp gets a small red glow back. Gemini, old vs new sky, both orders: Persona red-and-black 7.1 vs 3.2, its **nine video screens painted into the buildings** (bezels, frames, brackets) and keyed clear (`square.webp`). The ads are **live LED content behind the picture**, each mapped onto its measured four corners (`rectToQuad`, 5% overscan under the bezel), with an LED dot grid and a glow of its own colour spilling onto the frame: NOW SHOWING / SIDE QUESTS in cut-out letters (the big centre screen), LOOK CLOSER (tall), WANTED JOHN NGUYEN, our spinning star on halftone, BREAK THE ROUTINE, STEAL THE SHOW, NEW ? - **NEXT EPISODE**: every story page ends with an anime "next time" card. - **Slam-in on scroll** (Anime.js): page blocks that start below the fold punch up into place when you reach them. It only moves the separate `translate`/`rotate`/`scale` properties through one `--slam` variable, so it never clashes with GSAP or hover lifts, and nothing is ever hidden.
- **Pages build in while the wipe lifts** (the entrance starts at the swap, under the cover). Never show a finished page, blank it, then rebuild it.
- Board return (iris) opens right away; no long solid-red hold.
- Animate transform/opacity; never `transition: all`.

## 8. Sound

- **On by default (Nov 19, John: "the audio should be on by default, and users can turn it on or off from there").** Browsers allow no audio before the visitor's first tap, click or key, so nothing is created or downloaded before that (no audio engine, no clips, no music code: a test guards it); the first gesture anywhere starts the effects and the music. A visitor's own on/off choice is kept (`soundChosen`); saves from the off-by-default days don't count as a choice. The lock screen's switch reads TAP FOR SOUND until sound can play.
- **Sound survives leaving and coming back (Nov 19, John: "I turn the audio on, I exit, I come back and it doesn't work even though it says it's on... I have to toggle it off and on").** Two bugs, both fixed in `audio.js` (`initAudio`): the wake-up listened for `pointerdown`, but a finger touching down doesn't let a page start audio on phones (only lifting it, a click or a key does), so it failed once and stopped listening; and leaving the page put the audio engine to sleep with nothing to wake it. Now the wake-up listens to pointerup, click, touchend and key, and keeps listening until the sound really runs; leaving the page (another app, tab, a locked phone) pauses the sound, coming back resumes it where it left off (the music's loop continues from the same beat); after iOS interrupts audio (a call, Siri), the next tap brings it back. A test hides and shows the page and checks it never needs a toggle.
- **No glitch noise, on any headphones (Nov 19, John: "a glitchy bug sound... I'm using my AirPods").** The music's vinyl crackle (random pops, on purpose) read as a glitch: removed. Counted on an offline render, sharp ticks standing out of the music fell from 124 to 10 in 51 s (the 10 are the rim's own click). The music dipping under effects used to cut its fade short (a tiny click on every hover); it now holds where it is (`cancelAndHoldAtTime`). The audio engine asks for a little more buffer (`latencyHint: 'balanced'`) so a busy moment can't starve Bluetooth into crackling, and the music schedules 0.35 s ahead (was 0.2).
- ~~Off by default.~~ (superseded above) Speaker icon + a gentle "sound?" hint. **The sound button calls out until sound has been on once (Nov 19, John: "more noticeable, but not too big... grab slightly more attention"):** same size, but a red misprint sits under its white shadow, its X is red, and every few seconds the X snaps into two red sound waves (hard steps, no fades). After the first time sound is on it calms down for good (`jn-sound-seen`). Still with reduced motion (the red stays). Browsers block audio until a gesture; music resumes on the first click if it was on last visit.

- `npm test` (Playwright, desktop + phone, including a motion-on suite).

- **The biggest text on the first screen (the title hook) never fades in from opacity 0.** It slides in but is visible from the first frame, because Lighthouse times "largest paint" from when it becomes visible (Nov 18: the fade cost ~0.5s of LCP; GitHub's CI scored 83). CI Lighthouse takes the median of 3 runs, because one run on a shared runner is too noisy. Google Fonts load without blocking the first paint (`media="print"` + onload swap, `display=swap`, a `<noscript>` fallback): it saved ~0.9s of blocked rendering on phones and the layout is identical once fonts arrive.
- **The train's side is drawn by the GPU (Nov 18, John: "the quality degrades on top of the cart").** The 2D canvas cut the side into 5px slices, but a plane in perspective grows taller along its length, so each slice left a 4-5px step on the roof and the red stripe, worst right in front of the camera. `src/fx/sidegl.js` draws the side as one true-perspective WebGL2 surface with the full-resolution art (1828px tall, mipmapped; low-memory phones keep the 912px copy), on its own layer between two 2D canvases (floor, light pools and the headlight wash below; nose, sparks, dust and headlights above), so nothing is copied between WebGL and 2D. Shader, upload and buffers are warmed up in idle time at the real size (the first frame had cost ~100 ms). Drawing went from 5.0 ms (max 34) to 1.2 ms (max 1.7) a frame. Without WebGL2 the old slices still draw.
- **The train has weight (Nov 19, John: "it looks and feels like a cutout... make it look heavy and feel heavy, don't make the textures look thin like an old game, make it feel like an actual subway train").** Same audited art, heavier rendering; every cue is physical and cel-shaded (hard bands, no soft gradients):
  - **Steel material** (the GPU shader in `src/fx/sidegl.js`, `uMat`): deeper blue-tinted steel (contrast curve 1.45, x0.8), hard shade bands (roof edge 50%, lower body 80% / 75% / 70% in steps toward the skirt), **bold ink outlines** found from the art's own panel lines, door seams and frames, and **light streaks fixed to the station** (world depth), so the car slides *under* the reflections of the ceiling lights the way real metal does.   - **Grounding:** its **reflection in the glossy floor** (the car mirrored in the floor plane, fainter in hard steps away from the platform edge, a little cooler; the warm window light is drawn over it, because light adds up), and a **dark gap** where the body meets the platform edge.

## 14. Lessons learned while building (technical design notes)

- **The page's largest text must not wait for the web fonts (Nov 19: CI's mobile Lighthouse fell to 0.66-0.86 twice after TAKE YOUR NOTES / TIME).** The largest text is the title's hook, under the loading screen. It was written in by the script, so it painted after main.js ran; the loading screen's letters ask for the brand fonts at the first frame, so the fonts often arrived first, and Lighthouse's simulation then counted the slow font download as part of the hook's paint (LCP flipped between 0.9 s and 2.4 s from run to run, for the old versions too). Now the title screen is **active with its hook in the HTML** (app.html), so it paints at the first frame, before any font or script (LCP 0.9 s on every run). While it waits for its fonts (`title-wait`, now also in the HTML) the title block is `visibility: hidden` except the hook and PRESS START, so the name filling in above it is not a layout shift (an invisible block's moves don't count; the first try, without this, scored 0.149 CLS in 1 run of 5). PRESS START stays visible (still at opacity 0): a hidden button can't take the keyboard focus, and without focus its pulse never pauses (two tests timed out). Measured: 0.96-1.00 over 5 runs, CLS ≤ 0.017. The seal's spin was moved onto its own `<svg>` (a composited turn; turning a group inside one SVG repainted the text path every frame) and the loader has `contain: layout paint style`.
- **A deep link to THE PLAN must paint its words at once (Nov 21: mobile Lighthouse on `/#/board` scored ~0.6 with LCP ~7 s, while `/` scored 0.97).** Three causes, one fix each, and the board looks exactly the same (desktop and phone screenshots pixel-identical to before; the cascade's end state matches to the 5th decimal): **(1)** the LCP was a **letter on the tower's LED billboard**. Live SVG `<text>` counts as page text, and it only appears once the 430 KB city picture has loaded, so the slow-phone estimate waited for the picture. The letters are now the **mask** and the LED dots show through it (`bbText-*` in `backdrop.js`): the same white dots, but a stencil, not text. **(2)** Then the LCP was the board's own words, held at opacity 0 by the entrance cascade while the fonts and the 760 KB of background art started. On a cold deep link THE PLAN is now **drawn finished at once** (`board.reveal(delay, built)`), because real visitors always have the loading screen over it (at least 1.6 s, then their click) while the 0.8 s cascade played unseen underneath; only automated browsers (Lighthouse, tests), which skip the loader, ever saw it. The cascade still plays after PRESS START, and coming back from a chapter is still the quick slam. **(3)** Drawn at once, the board showed its words before the web fonts and shifted when they swapped in (CLS 0.055: the role line wrapped to two lines on phones). **Width-matched stand-ins** now cover Barlow Condensed, Anton (after Impact) and Barlow Semi Condensed, like the Bebas and Special Elite ones (`tokens.css`, measured at 100px against Arial, Roboto and DejaVu; the narrow end is used so a stand-in never wraps where the real font wouldn't), limited to the Latin range so a symbol the brand fonts lack (the teaser's ▸) falls through to the same system font as before. The billboard ticker also rests until the city picture has arrived (it moved invisible letters, a layout every frame). Result, 3 runs each: `/#/board` 0.95-0.97, LCP 0.9-2.0 s, CLS ≤ 0.009; `/` unchanged (0.95-0.98, LCP 0.9 s; its CLS of ~0.07 in some runs, on the title hook, predates this). **Rule: any screen a visitor can land on from a URL must have its largest text visible from its first frame, and decorative moving text belongs in a mask or a canvas, not in `<text>`.**
- Each `.screen` is `position: fixed`, which makes its own layer. Anything that must sit between page content and fixed buttons (the scroll strip) has to live **inside** the screen.
- Elements hidden by an entrance animation can't take focus; focus after they appear.
- A newer navigation must cancel an older one's leftovers (title slam, page intro, case-file cut-in).
- Pulsing buttons look "unstable" to test robots; that is a test quirk (use force clicks), not a bug.
- Don't let a CSS cleanup remove a class used inside `:not(...)`; it changes specificity. Verify with computed-style diffs.
- Background art is cropped differently on tall screens; check portrait phones and tablets for stray shapes.
- A ResizeObserver must ignore "same size" events or it will cancel draw-in animations.
- Publishing: upload every referenced asset, remove old hashed files, then download the published copy and compare byte-for-byte (including the PDF).
- Commit often; the cloud workspace can restart and stop servers.
- **Never let personal data into git history.** The first commit once held the original PDF with the phone number, and the tests held part of the number. History was rewritten before the first push; tests now look for any phone-number pattern instead of storing real digits.
- `position: relative` added for hit slop must never be applied to absolutely pinned controls (it once pushed every pop-up header down on phones).
- Entrance animations can knock focus back to `<body>` after it was placed; re-check focus once a page has settled.
- Loading Google Fonts without blocking was first rejected (Nov 17: cut-out letters flashed in fallback fonts). Nov 18 it is back, done right: fonts load without blocking (phone LCP 2.4s to 1.4s, CI needed it), and the title's cut-out name, NGUYEN slab, role line and PRESS START **wait for their fonts** (`fontsReady()` in `core/util.js`, `.title-wait`) for at most ~1.2s after page start, then slam in. The hook shows at once (it is the LCP). Tested with fonts delayed 1.5s: no fallback flash inside the cap.
- The big outlined watermark words used to scroll forever (a marquee). Endless motion competes for attention; they now slide in once.
- Pop-ups on phones must never block a control: phone toasts let taps pass straight through. Desktop toasts show a draining yellow **fuse** (Watermelon/Sonner pattern) that pauses on hover.
- HUD buttons use **comic tooltips** (black slab, red offset, spike) that show the name and shortcut (`SOUND · M`, `MENU · CTRL K`) on mouse hover or keyboard focus; never on touch. No native `title` tooltips (they doubled up).
- Count-ups must never show a wrong headline number for long: the GPA counts from 3.50, not 0.
- The PROGRESS list is two columns with outline stars for "not yet" so all 8 rows fit a 900px-tall laptop.
- **Never put a CSS transition on a property GSAP animates** (Nov 18): the hub's lines had `transition: transform, opacity`, so GSAP's "start hidden" eased in over 0.15s and the finished screen flashed before it built, and the slide-in lagged. State styling (picked, read) uses the separate `scale` / `translate` properties; GSAP owns `transform` and `opacity`.
- Two `from()` tweens on the same letters end invisible (the second records the first's hidden start as its end). The first entrance animates the letters itself; hover previews animate them only after that.
- A delayed GSAP timeline doesn't hide its pieces until it starts; build it paused with `defaults: { immediateRender: true }` and play it with `delayedCall`.
- Test scripts that watch the page from an init script must observe `document`, not `document.documentElement` (it doesn't exist yet).
- **Screens sized in vw need `scrollbar-gutter: stable`** (Nov 18): THE PLAN was a hair taller than the screen, a scrollbar appeared, the vw-sized type shrank so it fit, the scrollbar left, the type grew back: the hub jittered 16px every frame and clicks never landed. A test now checks the hub holds still and doesn't overflow.
- **Smooth motion rules (Nov 21, from a friend's advice, measured at 4x slower CPU).** What he had right, now the rule: animate only `transform` / `translate` / `rotate` / `scale` / `opacity`, and prefer CSS animations or WAAPI (`el.animate`) to JS tweens for fire-and-forget motion, because those can run off the main thread. Done: the MENU open/close is CSS classes (`mn-in` / `mn-out`, `linear()` easings sampled from GSAP's back.out, cubic-bezier fallback); the chapter-title slam is WAAPI; the back button hides with `translate` not `top`; the project-header dots move with `transform` not `background-position`; the scroll meter caches its measurement (ResizeObserver) instead of reading `scrollHeight` every scroll; pointer parallax writes each layer's own `transform` instead of an inherited `--px` / `--py` that restyled the whole backdrop; the LED ring only writes when a value changes. Measured: title mouse-move style work 447 ms to 72-95 ms, menu open layouts 45 to 25, style recalcs 122 to 66. What he had wrong, so left alone: "position is always the slow one" (a one-time layout is fine; the SAVE DATA card height and the grid-row reveal really change the page's flow, and faking them with scale would squash the text); "JS animation is always bad" (GSAP stays for interactive, interruptible motion like menu selection and the hub, where it is cheap); "make everything a layer" (`will-change` only on things that move all the time; extra layers cost phone memory). The train's GPU warm-up looked heavy in one profile but runs once at start (steady idle: about 2 ms script per second).
